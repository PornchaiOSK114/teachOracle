## 2. ข้อเท็จจริงจากเอกสาร Stripe (ตรวจแล้ว)

### ช่องใส่จำนวน — ทำได้

Payment Links รองรับ **adjustable quantity** ตั้งได้ทั้งจากหน้า Dashboard และ API

- **Dashboard** สร้าง payment link → หัวข้อ **Payment page › Product** → ติ๊ก **Let customers adjust quantity** ตั้งค่าต่ำสุด/สูงสุดได้
- **API** ใส่ `line_items[].adjustable_quantity` พร้อม `minimum` / `maximum`

ลูกค้าจะเห็นตัวปรับจำนวนบนหน้าจ่ายเงินของ Stripe เอง เราไม่ต้องเขียน UI

### พร้อมเพย์ — ใช้กับ Payment Links ได้

| หัวข้อ | ค่า |
| :--- | :--- |
| ประเทศลูกค้า | ไทย |
| สกุลเงิน | THB เท่านั้น |
| รองรับ Payment Links | ✅ ใช่ |
| รองรับ Checkout | ✅ ใช่ (ยกเว้นโหมด subscription และ setup) |
| คืนเงิน | ได้ ทั้งเต็มจำนวนและบางส่วน |
| Manual capture | ❌ ไม่ได้ |

### ⚠️ กับดักของพร้อมเพย์ที่ต้องรู้ก่อนเปิดขาย

1. **ชื่อที่ลูกค้าเห็นในแอปธนาคาร แก้ไม่ได้**
   ขึ้นว่า `STRIPE PAYMENTS (THAILAND) LTD` ไม่ใช่ชื่อร้านเรา
   ต้องเขียนบอกไว้บนหน้าเว็บ ไม่งั้นลูกค้าจะงงว่าโอนให้ใคร

2. **สแกน QR เดิมซ้ำ = เสียเงินซ้ำ**
   Stripe บอกตรง ๆ ว่าถ้าลูกค้าสแกน QR เดิมอีกครั้งหลังจ่ายสำเร็จแล้ว เงินจะถูกหักอีกรอบ
   เงินส่วนเกินจะเข้ายอดคงเหลือของเรา แล้ว **เราต้องคืนเงินให้ลูกค้าเองนอกระบบ Stripe**
   ควรเขียนเตือนบนหน้าเว็บว่า "จ่ายแล้วอย่าสแกนซ้ำ"

3. **คืนเงินต้องรอลูกค้าให้เลขบัญชี**
   Stripe จะอีเมลไปถามเลขบัญชีที่ลูกค้าใช้โอนมา ถ้าลูกค้าไม่ตอบ การคืนเงินอาจล้มเหลว
   แปลว่านโยบายคืนเงินของเราจะช้ากว่าบัตรเครดิต ควรเขียนให้ชัดว่าใช้เวลากี่วัน

4. **ไม่มี dispute แบบบัตร** — ความเสี่ยงโดนโกงต่ำ แต่ก็ไม่มีกลไกโต้แย้งเหมือนบัตร

## 3. การส่งไฟล์อัตโนมัติ — ต้องใช้ webhook เท่านั้น

Stripe เขียนเตือนไว้ชัดว่า **ห้ามส่งของโดยอาศัยหน้า success page อย่างเดียว**
เพราะลูกค้าอาจจ่ายเงินสำเร็จแล้วเน็ตหลุดก่อนหน้านั้นจะโหลด

ต้องดัก event ฝั่ง server:

| Event | เมื่อไหร่ |
| :--- | :--- |
| `checkout.session.completed` | จบ checkout (แต่เงินอาจยัง**ไม่**เข้า ถ้าเป็นวิธีจ่ายแบบหน่วงเวลา) |
| `checkout.session.async_payment_succeeded` | เงินเข้าจริงทีหลัง |
| `checkout.session.async_payment_failed` | จ่ายไม่สำเร็จทีหลัง |

**❗ ต้องเช็ค `payment_status` ก่อนส่งไฟล์เสมอ** ไม่ใช่เห็น `completed` แล้วส่งเลย
พร้อมเพย์เป็นแบบลูกค้ากดยืนยันเอง (customer-initiated) มีโอกาสเข้าเคสหน่วงเวลา
ตอนลงมือต้องทดสอบด้วยของจริงว่าพร้อมเพย์ยิง event ตัวไหน

ข้อกำหนดของฟังก์ชันส่งไฟล์ตามเอกสาร Stripe:

- ต้องทนถูกเรียกซ้ำหลายรอบด้วย session id เดิม (idempotent) — ห้ามส่งซ้ำ
- ดึง Checkout Session พร้อม expand `line_items` เพื่อ**อ่านจำนวนที่ลูกค้าสั่งจริง**
- บันทึกสถานะว่าส่งแล้วลงที่เก็บข้อมูลของเราเอง

> จุดนี้ต่อกับของเดิมได้พอดี — ตอนนี้เรามี Google Sheet เป็นที่เก็บออเดอร์
> และ Apps Script ที่ส่งอีเมลแนบไฟล์อยู่แล้ว อาจให้ Stripe ยิง webhook มาที่
> Apps Script Web App (`doPost`) แล้วใช้กลไกส่งไฟล์เดิม ไม่ต้องสร้างระบบใหม่ทั้งชุด

## 5. เรื่องที่ยังต้องตัดสินใจก่อนลงมือ

### 5.1 "ซื้อ 3 เล่ม" ของ E-Book แปลว่าอะไร

ไฟล์ PDF ก๊อปได้ไม่จำกัด การขายหลายเล่มจึงต้องนิยามให้ชัดก่อน มี 3 แนว

| แนว | ลูกค้าได้อะไร | งานที่ต้องทำ |
| :--- | :--- | :--- |
| ก. ขายเป็น "สิทธิ์" | ส่งไฟล์เดิมไปอีเมลเดียว ระบุในอีเมลว่าซื้อ N สิทธิ์ ผู้ซื้อไปแจกเอง | น้อยสุด ทำได้ทันที |
| ข. เก็บอีเมลผู้รับทีละคน | ส่งแยกไปแต่ละอีเมล | ต้องมีช่องกรอกอีเมล N ช่อง — custom fields ของ Stripe จำนวนช่องคงที่ ไม่ยืดตามจำนวน ต้องเก็บทีหลังผ่านฟอร์มเรา |
| ค. ฝังลายน้ำรายเล่ม | PDF แต่ละไฟล์มีชื่อผู้ซื้อฝังอยู่ | งานหนักสุด ต้องสร้าง PDF ตอนส่ง |

**ยังไม่ได้เลือก** — ต้องถามเจ้าของเว็บว่าเคสจริงคือใคร (บริษัทซื้อให้ทีม? อาจารย์ซื้อให้นักเรียน?)

### 5.2 ซื้อหลายเล่มแล้วลดราคาไหม

เช่น 5 เล่มขึ้นไปลด 10%
**ยังไม่ได้ตรวจว่า Payment Links รองรับ volume pricing แบบขั้นบันไดกับสินค้าจ่ายครั้งเดียวหรือไม่**
ต้องเช็คตอนลงมือ ถ้าไม่รองรับอาจต้องแยกเป็นหลาย payment link หรือใช้ coupon

### 5.3 ค่าธรรมเนียม

ตอนนี้รับโอนพร้อมเพย์ตรงเข้าบัญชี **ค่าธรรมเนียม 0 บาท** แต่ต้องเช็คสลิปเอง
ถ้าย้ายไป Stripe จะเสียค่าธรรมเนียมแลกกับความอัตโนมัติ
**ยังไม่ได้เช็คอัตราจริงของ Stripe ประเทศไทย** — ต้องดูตอนสมัคร อย่าเดา

### 5.4 VAT

Stripe Tax คำนวณ VAT ไทยได้เฉพาะกรณี**ผู้ขายอยู่นอกประเทศไทย** (remote seller)
ผู้ขายที่อยู่ในไทยเอง Stripe Tax ไม่รองรับการคำนวณให้
เกณฑ์จดทะเบียน VAT ของไทยคือรายได้ 1.8 ล้านบาท
**ผมไม่ใช่ที่ปรึกษาภาษี** เรื่องนี้ควรถามบัญชีก่อนตัดสินใจ

### 5.5 อยู่ร่วมกับระบบเดิมยังไง

ตอนนี้มี 2 ทาง: โปรศิษย์เก่า 490 (ฟอร์ม + โอนตรง) กับราคาเต็ม 790 (ยังไม่เปิด)
ต้องตัดสินใจว่าเมื่อเปิด Stripe แล้ว:

- ปิดฟอร์ม Apps Script ทิ้งเลย หรือเก็บไว้เป็นทางเลือกสำหรับคนไม่อยากผ่าน Stripe
- โปรศิษย์เก่ายังใช้รหัสกรองอยู่ไหม ถ้าย้ายไป Stripe จะกรองยังไง (coupon code? payment link ลับ?)

## 6. ที่จะทำตอนเริ่มเฟส Stripe

1. ตัดสินใจข้อ 5.1 ถึง 5.5 ให้ครบก่อน
2. สมัคร/ยืนยันบัญชี Stripe ประเทศไทย เปิดพร้อมเพย์ใน Dashboard › payment methods
3. สร้าง Product + Price แล้วสร้าง Payment Link เปิด adjustable quantity
4. ตั้ง branding, terms URL, refund policy, custom domain (ถ้าเอา)
5. ตั้ง success URL กลับมาที่ `teedba.com` พร้อม `{CHECKOUT_SESSION_ID}`
6. เขียน webhook handler + ทดสอบด้วย Stripe CLI ก่อนของจริง
7. ทดสอบซื้อจริงด้วยพร้อมเพย์ 1 รายการ ดูว่า event ตัวไหนมาและ `payment_status` เป็นอะไร
8. เอา URL ใส่ `lib/site.ts` ที่ `buyUrl` (ตอนนี้อ่านจาก `NEXT_PUBLIC_STRIPE_LINK_ORACLE26` ยังว่างอยู่ ปุ่มราคาเต็มจึง disable)

## 7. ส่วนที่อยากลอกจากต้นแบบมาใส่หน้าเรา (ไม่เกี่ยวกับ Stripe ทำก่อนได้)

เรียงตามความคุ้มค่าต่อการขาย

1. **FAQ** — เขาตอบเรื่องต้องเขียนโปรแกรมเป็นไหม / มีค่าใช้จ่ายอื่นไหม / ได้ไฟล์ยังไง / อัปเดตฟรีไหม เราตอบได้หมด เขียนไม่นาน
2. **"เล่มนี้เหมาะกับใคร"** — คัดคนอ่านให้ตรงกลุ่ม ลดคนซื้อผิดแล้วมาขอคืนเงิน
3. **สารบัญเป็นข้อความ** — ตอนนี้เราเป็นรูป Google อ่านไม่ออก เสีย SEO ฟรี ๆ
4. **รีวิวจากผู้เรียน** — ต้องขอจากศิษย์เก่าจริง ใช้เวลารอ เริ่มเก็บได้เลย
5. **นโยบายคืนเงิน** — ต้นแบบไม่มี แต่เรามีน่าจะดีกว่า เพราะพร้อมเพย์คืนเงินยาก ควรบอกล่วงหน้าว่าทำได้แค่ไหน
