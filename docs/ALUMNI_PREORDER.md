ฟอร์มสั่งซื้อที่เราเขียนเอง ลูกค้า **ไม่ต้องล็อกอินอะไรทั้งนั้น** แนบสลิปได้
ข้อมูลลง Google Sheet ไฟล์สลิปลง Google Drive แล้วส่งหนังสือทางอีเมลอัตโนมัติ

เปิดรับถึง **วันจันทร์ที่ 31 สิงหาคม 2569 เวลา 23:59** เริ่มส่งไฟล์ **1 กันยายน 2569**

## ทำไมไม่ใช้ Google Form

Google Form ที่มีช่องอัปโหลดไฟล์ **บังคับให้ลูกค้าล็อกอินบัญชี Google เสมอ ปิดไม่ได้**
ลูกค้าที่เปิดจากมือถือแล้วไม่ได้ล็อกอินอยู่จะหลุดตั้งแต่ยังไม่ทันเห็น QR

Web App ที่เรา deploy แบบ **Anyone** ไม่มีข้อจำกัดนี้ ไฟล์สลิปถูกสร้างด้วยบัญชีของคุณ ไม่ใช่ของลูกค้า
จึงไม่ต้องให้ใครล็อกอินเลย

## ขั้นที่ 1 เตรียมชีตและไฟล์

1. สร้าง Google Sheet เปล่า ตั้งชื่อ `ออเดอร์ Oracle 26ai ราคาศิษย์เก่า` ไม่ต้องพิมพ์หัวตารางเอง
2. วางไฟล์ **PDF หนังสือ**, **ZIP สคริปต์แล็บ** และ **รูป QR ชื่อขึ้นต้นว่า `QR.`** (เช่น `QR.jpg`) ไว้ในโฟลเดอร์

   ```
   https://drive.google.com/drive/folders/1-Mi2EuJD3dC9pA2ue2c_xdbm9sowKFfx
   ```

3. **คลิกขวาที่ไฟล์ QR › Share › Anyone with the link** ไม่งั้นลูกค้าจะเห็นเป็นรูปแตก

> ⚠️ ห้ามวางไฟล์อื่นปนในโฟลเดอร์นี้ เพราะสคริปต์แนบทุกไฟล์ที่ไม่ใช่ QR ส่งไปให้ลูกค้า

## ขั้นที่ 2 วางโค้ด 3 ไฟล์

ในชีต ไปที่ **Extensions › Apps Script** แล้วสร้างไฟล์ให้ครบ 3 ไฟล์

| ไฟล์ในโปรเจกต์ | สร้างยังไง | เอาเนื้อหาจาก |
| :--- | :--- | :--- |
| `Code.gs` | มีอยู่แล้ว ลบของเดิมทิ้งแล้ววางทับ | [`apps-script/Code.gs`](./apps-script/Code.gs) |
| `WebApp.gs` | กด **+ › Script** ตั้งชื่อ `WebApp` | [`apps-script/WebApp.gs`](./apps-script/WebApp.gs) |
| `Form.html` | กด **+ › HTML** ตั้งชื่อ `Form` | [`apps-script/Form.html`](./apps-script/Form.html) |

ชื่อไฟล์ต้องตรงเป๊ะ โดยเฉพาะ `Form` เพราะโค้ดเรียกด้วยชื่อนี้

กด Save แล้วเลือกฟังก์ชัน `setupOnce` กด **Run**
ครั้งแรกจะขึ้นหน้าขออนุญาต กด **Advanced › Go to ... (unsafe) › Allow**

ที่ขึ้นคำว่า unsafe เพราะเป็นสคริปต์ที่เราเขียนเอง ไม่ได้ผ่านการรีวิวของ Google ไม่ใช่เรื่องผิดปกติ

จากนั้นกลับมาที่ชีต จะมีเมนู **ส่งหนังสือ** โผล่ขึ้นมา

## ขั้นที่ 3 ตั้งรหัสศิษย์เก่า

เมนู **ส่งหนังสือ › ตั้งรหัสศิษย์เก่า** แล้วพิมพ์รหัสที่จะใช้จริง

> **ห้ามพิมพ์รหัสจริงลงในไฟล์ใด ๆ ของ repo นี้** รวมถึงเอกสารฉบับนี้
> โฟลเดอร์ `docs/` ถูก push ขึ้น GitHub รหัสที่พิมพ์ลงไปจะหลุดไปกับ repo ทันที
> อยากจดกันลืม ให้จดไว้ในที่ส่วนตัว เช่น password manager หรือโน้ตในเครื่อง

รหัสถูกเก็บใน **Script Properties** ของโปรเจกต์ ไม่ได้อยู่ในไฟล์โค้ด และ**ไม่เคยถูกส่งไปฝั่งเบราว์เซอร์**
ลูกค้ากด View Source ก็ไม่เห็น เพราะการตรวจรหัสเกิดขึ้นฝั่ง server ทั้งหมด

การเทียบรหัสไม่สนตัวพิมพ์เล็กใหญ่ ลูกค้าพิมพ์ตัวเล็กมาก็ผ่าน (ทดสอบแล้ว)

เหตุผลที่ต้องทำแบบนี้: ไฟล์ในโฟลเดอร์ `docs/` ถูก push ขึ้น GitHub ถ้าพิมพ์รหัสลงไปในโค้ด รหัสจะหลุดไปกับ repo

## ขั้นที่ 4 Deploy เป็น Web App

1. ในหน้า Apps Script กด **Deploy › New deployment**
2. กดรูปเฟือง เลือก **Web app**
3. ตั้งค่าให้ตรงตามนี้

   | ช่อง | ค่า |
   | :--- | :--- |
   | Description | `ฟอร์มสั่งซื้อ ราคาศิษย์เก่า` |
   | Execute as | **Me (อีเมลคุณ)** |
   | Who has access | **Anyone** |

4. กด **Deploy** แล้วคัดลอก URL ที่ลงท้ายด้วย `/exec`

> **Execute as: Me** คือหัวใจ เพราะทำให้ไฟล์สลิปถูกสร้างด้วยสิทธิ์ของคุณ ลูกค้าจึงไม่ต้องล็อกอิน
> ถ้าเผลอเลือก **Who has access: Only myself** ลูกค้าจะเปิดไม่ได้เลย

**ทุกครั้งที่แก้โค้ด ต้อง Deploy ใหม่** ไปที่ **Deploy › Manage deployments › ดินสอ › Version: New version › Deploy**
URL จะเหมือนเดิม ไม่ต้องไปแก้ที่ Vercel อีก

## ขั้นที่ 5 เอา URL ขึ้นเว็บ

URL ของฟอร์มถูกใส่ไว้ใน `lib/site.ts` ตรง `promo.orderUrl` เรียบร้อยแล้ว
push ขึ้น GitHub แล้ว Vercel build เสร็จ ปุ่มก็ทำงานทันที **ไม่ต้องตั้งค่าอะไรเพิ่มที่ Vercel**

ที่ใส่ค่าจริงลงไฟล์ได้เพราะ URL นี้เป็นลิงก์สาธารณะ ไม่ใช่ความลับ ใครกดปุ่มก็เห็นใน address bar อยู่แล้ว
(ต่างจากรหัสศิษย์เก่า ซึ่งห้ามใส่ในไฟล์ใด ๆ ของ repo เด็ดขาด)

**ถ้าวันหลัง deploy ใหม่แล้ว URL เปลี่ยน** ไม่ต้องแก้โค้ด ตั้งตัวแปรนี้ที่
Vercel › Settings › Environment Variables แล้ว **Redeploy** ค่าจะทับของในไฟล์เอง

```
NEXT_PUBLIC_ALUMNI_ORDER_URL = https://script.google.com/macros/s/....../exec
```

(ตัวแปร `NEXT_PUBLIC_` ถูกฝังตอน build แค่กด save ไม่พอ ต้อง redeploy ด้วย)

**ถ้า `orderUrl` เป็นค่าว่าง** ปุ่มจะ disable ขึ้นว่า "กำลังเปิดรับเร็ว ๆ นี้"
แต่**ลิงก์ทักเพจ Facebook ใต้ปุ่มยังใช้ได้ปกติ** ขายได้ทันทีแม้ฟอร์มล่ม

### ⚠️ แก้ฟอร์มแล้วต้อง deploy ยังไงให้ URL ไม่เปลี่ยน

ถ้าวันหลังแก้ `Form.html` หรือ `doGet` แล้วอยากให้ของใหม่ขึ้น:

**Deploy › Manage deployments › ดินสอ › Version: New version › Deploy**

ห้ามกด **New deployment** เพราะจะได้ URL ใหม่คนละอันกับที่อยู่ในเว็บ ลิงก์เดิมจะตายทันที

ส่วนฟังก์ชันที่เรียกจากเมนูในชีต (`sendPending`, `setupOnce`, ฯลฯ) รันที่โค้ดล่าสุดเสมอ
แก้ `Code.gs` แล้วกด Save ก็มีผลเลย ไม่ต้อง deploy

### ⚠️ การแชร์ไฟล์ใน Drive

โฟลเดอร์ `FOLDER_ID` เก็บทั้งไฟล์ที่จะส่งลูกค้าและรูป QR ปนกัน สิทธิ์ต้องเป็นแบบนี้เป๊ะ ๆ

| ไฟล์ | สิทธิ์ | ทำไม |
|---|---|---|
| ตัวโฟลเดอร์ | **Restricted** | เปิดสาธารณะเมื่อไหร่ = ใครได้ลิงก์โฟลเดอร์ก็โหลดหนังสือฟรี |
| `Oracle 26 ai SQL Tuning.pdf` | **Restricted** | สินค้าที่ขาย |
| `Oracle 26 ai SQL Tuning Lab.zip` | **Restricted** | สินค้าที่ขาย |
| `QR.jpg` | **Anyone with the link** | ลูกค้าที่ไม่ได้ล็อกอินต้องเห็นรูปนี้ในฟอร์ม |

ลำดับสำคัญ — ปิดโฟลเดอร์ก่อน แล้วค่อยเปิด `QR.jpg` ทีหลัง
เพราะการปิดโฟลเดอร์จะลบสิทธิ์ที่ไฟล์ข้างในสืบทอดมาด้วย

ชื่อไฟล์ QR ต้องขึ้นต้นด้วย `QR.` เป๊ะ ๆ (`QR.jpg`, `QR.png`) เพราะ `getQrImageUrl_()` หาด้วย regex `^QR\.`
ชื่อแบบ `QR code.jpg` หรือ `qr (1).jpg` จะหาไม่เจอ แล้วฟอร์มจะขึ้นข้อความสำรองแทนรูป

`getAttachments_()` ข้ามไฟล์ที่ขึ้นต้นด้วย `QR.` อยู่แล้ว ลูกค้าจึงไม่ได้รับ QR แนบไปกับอีเมลหนังสือ

## ขั้นที่ 6 ทดสอบก่อนประกาศ

ทำให้ครบ อย่าข้าม

- [ ] เปิด URL `/exec` ใน **หน้าต่าง Incognito ที่ไม่ได้ล็อกอิน Google** ต้องเปิดได้และไม่ถูกขอให้ล็อกอิน
- [ ] ใส่รหัสผิด เช่น `TTC123` ต้องขึ้นข้อความว่าเฉพาะศิษย์เก่า และไปต่อไม่ได้
- [ ] ใส่รหัสถูก ต้องเห็นหน้า QR และ **รูป QR ต้องขึ้นจริง ไม่ใช่รูปแตก**
- [ ] แนบรูปสลิปจากมือถือ กดส่ง ต้องขึ้นหน้าขอบคุณ
- [ ] เช็คว่าได้อีเมลตอบรับ และอีเมลแจ้งเตือน `[ออเดอร์ใหม่]` พร้อมลิงก์สลิปที่กดเปิดดูได้
- [ ] เช็คว่ามีแถวใหม่ในชีต ข้อมูลครบทุกช่อง
- [ ] เมนู **ส่งหนังสือ › ส่งอีเมลทดสอบมาหาตัวเอง** เปิดดูว่าไฟล์แนบครบและเปิดได้
- [ ] พิมพ์ `OK` ในคอลัมน์อนุมัติของแถวทดสอบ ต้องได้อีเมลพร้อมไฟล์แนบภายในไม่กี่วินาที
- [ ] พิมพ์ `OK` ซ้ำ ต้อง**ไม่**ส่งซ้ำ
- [ ] ลบแถวทดสอบและไฟล์สลิปทดสอบทิ้ง

## ช่องทางสำรอง Facebook

ใต้ปุ่มบนเว็บมีลิงก์ **ทักมาที่เพจ Facebook** เสมอ สำหรับคนที่ฟอร์มมีปัญหาหรืออยากถามก่อนซื้อ

ลูกค้าที่มาทางนี้ คุณ **พิมพ์แถวลงชีตเอง** 4 ช่อง (อีเมล ชื่อ เวลาโอน แล้วเว้นช่องสลิปไว้ก็ได้)
แล้ววันที่ 1 ก.ย. พิมพ์ `OK` เหมือนกัน ระบบส่งไฟล์ให้เหมือนกันทุกอย่าง เพราะสคริปต์อ่านจากชีต ไม่ได้อ่านจากฟอร์ม

บันทึกข้อความสี่ชุดนี้ไว้ใน **คำตอบที่บันทึกไว้ (Saved replies)** ของกล่องข้อความเพจ

## สิ่งที่ระบบนี้ทำและไม่ทำ

**ทำให้**

- ตรวจรหัสฝั่ง server รหัสไม่เคยหลุดไปฝั่งเบราว์เซอร์
- ย่อรูปสลิปในเครื่องลูกค้าก่อนอัป รูป 4 MB จากมือถือเหลือไม่ถึง 300 KB
- มีกับดักบอท (honeypot) และจำกัดชนิดกับขนาดไฟล์
- ใช้ LockService กันสองคนกดส่งพร้อมกันแล้วเขียนทับแถวเดียวกัน
- ถ้าส่งอีเมลไม่สำเร็จ ข้อมูลยังลงชีตครบ ลูกค้าไม่เห็น error ที่ทำให้เข้าใจผิดว่าสั่งไม่สำเร็จ

**ไม่ทำ**

- **ไม่ตรวจสลิปอัตโนมัติ** คุณต้องเปิดดูแล้วเทียบยอดในแอปธนาคารเอง
- **ไม่จำกัดจำนวนดาวน์โหลด** ส่งเป็นไฟล์แนบ ลูกค้าเก็บไว้ได้เลย
- **ไม่ได้ประทับชื่อผู้ซื้อลงใน PDF** ทำเพิ่มได้ทีหลังโดยไม่ต้องรื้อระบบเดิม
- **URL เป็นของ Google** (`script.google.com/...`) ไม่ใช่ `teedba.com` ถ้าอยากได้โดเมนตัวเอง ต้องทำหน้าบนเว็บแล้ว iframe เข้ามา ซึ่งเป็นงานอีกก้อน
